# 架构与数据流

## 组件

| 组件 | 职责 |
| --- | --- |
| `dashboard/` | 浏览器中的本地工作台：岗位池、岗位进展、简历资产、来源、笔记。 |
| `scripts/server.mjs` | 本地 HTTP API、静态页面托管和工作流编排。 |
| `db/` | SQLite schema、迁移和轻量查询层。 |
| `services/` | URL 解析、去重、岗位分析、简历生成、公开来源采集和进度计算。 |
| `ats/` | Greenhouse、Lever、通用表单的字段识别与安全填写。 |

## 核心流程

```text
岗位 URL / JSON / 手动录入
        ↓
规范化链接、公司别名与岗位名称
        ↓
去重 → 岗位池（待人工确认）
        ↓
确认岗位 → 生成或复用简历 → 创建投递进展
        ↓
辅助填表（不提交） → 人工提交 → 状态、事件与任务跟进
```

## 数据边界

- `jobs` 是岗位主记录，编号倒序展示，不会因状态变化移动。
- `applications` 记录实际投递过程；`tasks` 记录下一步行动，两者不互相替代。
- `resume_versions` 保存每个岗位版本与快照；删除岗位时可保留可复用简历。
- `notes` 为独立笔记，不与岗位记录强绑定。
- `profile.yaml`、数据库和生成文件属于本地私有数据，默认不进入 Git。

## 迁移原则

运行 `npm run migrate` 是幂等操作：新数据库创建完整表结构，已有数据库按缺失列升级并保留记录。每次改变 SQLite 查询模式时，应只为实际查询建立必要索引，并在迁移后执行 `PRAGMA optimize`。
